# Compact device-significant launch service

The staged JIT screen now prices a necessary subset of the device-selected significant-pair selector. The production geometry in `device_selection_shape` determines the number and sizes of CUDA nonzero blocks for full and tail source chunks without expanding a whole-job block list. Under the checked PyTorch 2.5.1/CUDA 12.4/CUB 2.3 source policy, every block launches one count reduction and two flagged-selection kernels. A block above 4,096 cells launches a second count reduction. Each nonempty block also launches a coordinate scatter. These launches occur even when the indexed writer emits no part, apart from the conditional scatter.

For a partition with `B` blocks, `B_large` blocks above 4,096 cells, retained-pair interval `[r_low,r_high]`, and largest block `C_max`, the mandatory launch-count interval is `3B + B_large + [ceil(r_low/C_max), min(r_high,B)]`. Each GPU's partitions sum their counts at that device's independent `kernel_launch_seconds / gpu_fraction` service. The two-GPU floor is the maximum across devices. The partial envelope also adds the count-transfer barrier on the *same* GPU before taking this maximum, preserving per-stream serial work while sharing other resources only once.

The function checks the source/output identity and geometry, the independently declared launch profile, and the current installed torch, CUDA runtime and GPU compute capability. The report records price and partition bindings. It still excludes eager selector kernels, count/select kernel body work, CPU dispatch, host waits, payload transport, queueing, writer work and final drain. Its high endpoint bounds this partial launch service, not completion time, and it cannot authorize a JIT switch. The existing count-transfer floor remains separate so its bytes are not charged twice.

For the worked 512-marker by 600,000-phenotype chunk, the shared geometry gives 293 selection blocks at a 1,048,576-cell cap and 4,688 blocks at a 65,536-cell cap. All blocks exceed 4,096 cells in both cases; the respective mandatory base launch counts are 1,172 and 18,752 before any scatter. These are structural counts, not measured durations or a recommendation to use either tile.

The A100 focused batch passed 46 tests after the same-GPU and immutable-price-snapshot additions. It compares compact counts with expanded source blocks for five full/tail shapes, checks empty and retained output, validates live runtime/profile and output bindings, and verifies that count and launch service join serially on each GPU. The final broad layout, occupancy and controller suite passed 312 tests after the subsequent sparse-scenario and source-pricing changes. This addition narrows one device-selected output gap; the full selector service and output-inclusive finite continuation remain the next gates.
